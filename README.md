# Snatch

Snatch is an offline-first, single-player arcade game built with Expo + React Native. It is designed for iPhone first and Android as well.

## The game loop
- Survive an endless three-lane run.
- Swipe left/right or use the lane buttons to move.
- Collect coins, build combos and climb up to a 5x score multiplier.
- Dodge hazards; use the timed dash to pass through danger.
- Collect shields for an extra layer of protection.
- Find rare battery pickups to instantly recharge your dash.
- Speed and spawn pressure increase as your score and level rise.

## Reasons to return
- A daily seeded run: every player gets the same deterministic obstacle sequence for that calendar day.
- Daily contract: collect 35 coins, score 500 in a run, and dodge 5 hazards in one run.
- Claim 75 coins + 100 XP after completing the contract.
- XP ranks, a daily streak, seven achievements, personal-best history and unlockable runner skins.
- Eight skins, bought with coins earned through play.
- Daily, weekly and all-time global leaderboard views.
- Shareable run results and haptic feedback controls.

## Tech
- Expo SDK 54 / React Native 0.81
- AsyncStorage for local progression, profile, and settings
- Expo Crypto for a secure random installation identifier
- Expo Haptics for tactile feedback
- Pure deterministic game engine separated from UI
- GitHub Actions runs game tests, a dependency audit, Expo Doctor, and an iOS export
- A reproducible 1024px app icon is generated by scripts/create-icon.mjs during install

## Run locally
1. Install Node.js 22 LTS.
2. Clone this repository and run npm install.
3. Run npx expo start.
4. Scan the QR code with Expo Go, or open an iOS simulator from a Mac.

## Tests
Run npm test to execute deterministic engine, progression, save-recovery, and input-moderation tests.

## iOS production build
1. Install EAS CLI: npm install -g eas-cli.
2. Sign in: eas login.
3. Link the project to an Expo account and configure Apple signing credentials.
4. Build: eas build --platform ios --profile production.

## Honest current limitations
- Player setup asks only for a display name and age. There is no account, email, password, or social sign-in. Both fields stay on the device; age is never uploaded.
- Global leaderboards use Supabase without user accounts. Only display name, score, run duration, game date, and a random installation ID are sent when a player submits a score.
- Common English and Russian profanity is filtered in the app before names are saved or submitted. Players can report names through GitHub Issues or hide a name locally. The issue tracker is public; never include personal information.
- The leaderboard has basic database validation, not cheat-proof server verification. A determined player may manipulate client-submitted scores.
- A local reset does not delete already-submitted online scores. Users can request online score removal through the public GitHub issue tracker; requests are reviewed manually.
- Privacy, terms, and cookie documents are in PRIVACY.md, TERMS.md, and COOKIES.md.
